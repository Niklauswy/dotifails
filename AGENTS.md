# Wysun Desktop

- `apps/python/` es la raíz de los paquetes Python (un paquete por app: `wysun_core`, `wysun_music`, `wysun_files`, `wysun_media`, `wysun_player`, `wysun_processes`, `wysun_settings`, `wysun_services`; nada suelto). Las utilidades del día a día también son un paquete cada una (`wysun_lanshare`, …), con su orden en `MODULES` de `bin/wysun` (`wysun lanshare`); no hay `apps/tools` ni `wysun tools`. Se ejecutan como módulos (`python3 -P -m paquete`) con esa raíz en `PYTHONPATH`, que fijan `bin/` y el shell (`Paths.python()`); no se añaden rutas a `sys.path`.
- `bin/wysun` es el único punto de entrada: superficies y acciones del shell por IPC (`wysun SUPERFICIE` alterna cualquiera; la lista vive solo en `apps/shell/wysun/WysunBridge.qml`, `wysun-shell surfaces`) y apps/servicios con `python3 -P -m`. No se añaden alias ni lanzadores sueltos; los retirados se listan en `RETIRED_COMMANDS` de `installer/main.py` para que una actualización los quite.
- La arquitectura completa (estructura, runtime, instalación, rollback, atajos/tema/ajustes) está en `ARCHITECTURE.md`; léelo antes de reorganizar.
- `apps/shell/` es la barra y los paneles de Quickshell para la sesión Wysun / Hyprland, con el plugin C++ `Wysun.*` (`plugin/`). El runtime privado (Qt 6.9.3, Quickshell, libcava, M3Shapes, plugin) se construye con `installer/runtime_build.py` en `~/.local/share/wysun/runtime`; tras tocar `plugin/` ejecuta ese script y reinicia solo el shell (`pkill -x quickshell; setsid wysun-shell &`). `config/.config/wysun/hyprland.lua` contiene la configuración del compositor (Hyprland 0.55.x en Lua).
- `apps/recorder/` es la fuente integrada de Wysun Recorder; el repositorio histórico `loom` no se usa para distribuirlo ni desarrollarlo. Las capturas de pantalla (selector, anotación y OCR) las hace el shell en `apps/shell/modules/areapicker` (`wysun-shell screenshot`).
- La aplicación instalada vive en `~/.local/share/wysun/app/`. No editar esa copia directamente: las actualizaciones comprueban su integridad y conservarían la edición como conflicto.
- Para cambios de Wysun pedidos para el escritorio activo, probar primero y después desplegar con `wysun update` (desde este repositorio, la fuente registrada: hace `git pull --ff-only`, que no hace nada si la copia está al día o por delante, y aplica). Termina con `wysun reload` y reinicia solo el shell si cambió `apps/shell`. Si informa conflictos, revisar `incoming/` del respaldo. Comprobar la apertura real de los menús afectados antes de afirmar que el cambio está activo. `./instalar.sh` (sin opciones) instala todo en un equipo nuevo; no hay instalador gráfico ni modos `--*-only`.
- Wysun es el único nombre, también técnico: rutas `~/.local/share/wysun`, `~/.config/wysun`, `~/.local/state/wysun`, sockets `wysun-*`, variables `WYSUN_*`, CLI del instalador `wysun-install`. `tests/test_legacy_names.py` impide volver a los nombres anteriores. Las versiones de captura se instalan separadas de los datos y no se retiran mientras puedan usarlas procesos activos.
- `wysun update` aplica solo los componentes del recibo del equipo y repite paquetes, sesión, arranque, Neovim y Flatpaks solo cuando cambian sus entradas (`system_inputs` en `installer/main.py`); nunca toma archivos que no administraba. Despliega `config/.config/wysun/hyprland.lua`: si cambian atajos, actualizarlo ahí; un `hyprland.lua` editado en el equipo queda como conflicto (se conserva) hasta reconciliarlo. Los cambios llegan a otros equipos solo si están en `main` del repositorio.
- Mantener notas, colores, historial, conexiones y cualquier otro dato privado fuera del repositorio. Se almacenan separados de `app/`.
- Credenciales (tokens, logins y cookies de CLIs como Claude Code, Codex u OpenCode): el código de Wysun puede leerlas en ejecución cuando mejoren una función y no añadan riesgo, solo para consultar los datos del propio usuario a su proveedor. Se leen justo antes de usarlas, viajan solo por HTTPS al host oficial, nunca se escriben, renuevan, registran, cachean ni aparecen en salidas, avisos o errores, y una prueba con credenciales falsas lo comprueba. El agente nunca abre ni imprime esos archivos reales (ni `cat`, ni lecturas de prueba): solo escribe el código y lo valida con HOME temporales y credenciales sintéticas. Sin cookies del navegador salvo autorización expresa.
- No reiniciar Hyprland, cerrar otras aplicaciones ni reinstalar todo el entorno para actualizar un panel.
- Temas: Wysun tiene **un solo estilo, Material You**: no hay temas fijos. El color y el acento salen siempre del wallpaper actual (`~/.local/state/wysun/scheme.json`, que escribe `wysun scheme`) y la única elección del usuario es el modo: `auto` (lo deduce del fondo), `light` o `dark`. La selección vive en `~/.config/wysun/theme.json` como `{"mode": ...}`. Un cambio de modo o de wallpaper debe aplicarse en vivo a lanzador, utilidades, Music, Files, Settings, Recorder y Quickshell (incluida la captura de pantalla). El wallpaper se elige solo con el carrusel (`Super+Shift+W`, `wysun shell wallpapers`).
- Toda UI nueva o modificada (Qt, Recorder, QML) toma colores, radios, espaciado, tipografía, material, iconos y movimiento de los tokens del tema, nunca de valores literales. Probarla en claro y oscuro y con wallpapers de colores distintos. Las excepciones (colores semánticos de estado, muestras de color del usuario) se declaran explícitamente. Las apps de captura se instalan por versiones separadas: leen la selección en ejecución y no importan código de `~/.local/share/wysun/app/`.
- Los tokens viven en `apps/python/wysun_core/tokens.json`; el runtime es `wysun_core/theme.py` (sin Qt) y `wysun_core/qt_theme.py`. El Recorder los recibe con `wysun_core` dentro de cada release, sin copias a mano. El esquema es el 3, con los nombres del shell (`rounding.*`, `spacing.*`, `padding.*`, `font.*`, `anim.*`); el instalador lo copia a `~/.local/share/wysun/theme/tokens.json`, que el plugin del shell lee al arrancar (`tokens.hpp` es solo respaldo; no hay `shell-tokens.json`). Quickshell lee los colores de `~/.local/state/wysun/scheme.json` (`apps/shell/services/Colours.qml`), con `palettes.<modo>.scheme` del JSON como respaldo. Fuentes: Google Sans Flex y CaskaydiaCove, empaquetadas. `tests/test_theme_literals.py` rechaza colores literales; las excepciones llevan `theme-exception: motivo`. Guía: `docs/themes.md`.
- Base QML compartida para las apps que migran a QML (Music, Files): biblioteca pura `apps/qml/WysunM3` (sin `Quickshell`, `qs.*` ni `Wysun.*`) sobre PySide6 en el venv `~/.local/share/wysun/qml-runtime`, que usa el Qt del runtime del shell. Guía y catálogo: `docs/qml-base.md`. Sus pruebas (`tests/qml/check_*.py`) corren con el Python del venv: `python3 -m unittest tests.test_qml_runtime -v`; la galería es `python3 -m wysun_qml`.
- Comprobaciones relevantes: `python3 -m unittest discover -s tests -v`, `python3 -m unittest discover -s tests/wysun_app -t tests`, `python3 -m unittest discover -s tests/shell_bridge -t tests`, `QT_QPA_PLATFORM=offscreen python3 tests/utility_ui.py`, `python3 tests/check_manifest.py`. Ejecutar también `python3 apps/recorder/run_tests.py` y `python3 tests/wysun_installed_smoke.py`, con medios serializados. Las pruebas de sockets y escritorio necesitan acceso a la sesión; un bloqueo del sandbox no demuestra un fallo del producto.
- La sesión Wysun / Hyprland usa `apps/shell/` y el componente `wayland`, activo por defecto. No cambiar el login ni el gestor de acceso, no instalar dependencias del host ni reiniciar audio/portales sin autorización expresa. Validar con HOME/XDG temporales y medios sintéticos; pruebas de medios/compositor serializadas.
- El registro de sesión es independiente y reversible con `installer/session_registration.py`; nunca modificar por esa vía la sesión predeterminada ni el gestor de acceso. `docs/wayland.md` detalla preparación y recuperación.
