# Wysun Desktop

- `apps/wysun/` es la fuente del lanzador y sus paneles. Las copias históricas en otros directorios no son la fuente de desarrollo.
- La arquitectura completa (estructura, runtime, instalación, rollback, atajos/tema/ajustes) está en `ARCHITECTURE.md`; léelo antes de reorganizar.
- `apps/shell/` es la barra y los paneles de Quickshell para la sesión Wysun / Hyprland, con el plugin C++ `Wysun.*` (`plugin/`). El runtime privado (Qt 6.9.3, Quickshell, libcava, M3Shapes, plugin) se construye con `installer/runtime_build.py` en `~/.local/share/wysun/runtime`; tras tocar `plugin/` ejecuta ese script y reinicia solo el shell (`pkill -x quickshell; setsid wysun-shell &`). `config/.config/wysun/hyprland.lua` contiene la configuración del compositor (Hyprland 0.55.x en Lua).
- `apps/capture/` es la fuente integrada de Wysun Recorder; el repositorio histórico `loom` no se usa para distribuirlo ni desarrollarlo. Las capturas de pantalla (selector, anotación y OCR) las hace el shell en `apps/shell/modules/areapicker`; la app Qt Wysun Screenshot se retiró y `wysun screenshot`/`wybie-screenshot` solo redirigen al shell.
- La aplicación instalada vive en `~/.local/share/orbit/app/`. No editar esa copia directamente: las actualizaciones comprueban su integridad y conservarían la edición como conflicto.
- Para cambios de Wysun pedidos para el escritorio activo, probar primero y después desplegar con `./instalar.sh --orbit-only`. Si termina sin conflictos, ejecutar `~/.local/bin/orbit reload` en la sesión gráfica. Comprobar la apertura real de los menús afectados antes de afirmar que el cambio está activo. El instalador completo usa el mismo código.
- `--wysun-only` es un alias de `--orbit-only`. Wysun es el nombre público; conservar rutas de datos, namespaces y comandos técnicos anteriores para mantener compatibilidad. Las versiones de captura se instalan separadas de los datos y no se retiran mientras puedan usarlas procesos activos.
- `--orbit-only` no instala dependencias ni cambia atajos. Si cambian, actualizar `config/.config/wysun/hyprland.lua` y migrar cuidadosamente la configuración activa con respaldo, preservando otras asignaciones del usuario y comprobando conflictos.
- Mantener notas, colores, historial, conexiones y cualquier otro dato privado fuera del repositorio. Se almacenan separados de `app/`.
- No reiniciar Hyprland, cerrar otras aplicaciones ni reinstalar todo el entorno para actualizar un panel.
- Temas: Wysun tiene dos estilos, **Space Black** (variantes `space-black`, `tokyo`, `severance`: misma estructura, otra paleta) y **Fluent** (tipo Windows 11, variantes `light` y `dark`). La selección vive en `~/.config/orbit/theme.json` (`style` + `variant`; el formato antiguo `{"id": ...}` se sigue aceptando). Un cambio de estilo o variante debe aplicarse en vivo a lanzador, utilidades, Music, Files, Settings, Recorder y Quickshell (incluida la captura de pantalla).
- Toda UI nueva o modificada (Qt, Recorder, QML) toma colores, radios, espaciado, tipografía, material, iconos y movimiento de los tokens del tema, nunca de valores literales. Probarla en los dos estilos y en todas sus variantes. Las excepciones (colores semánticos de estado, muestras de color del usuario) se declaran explícitamente. Las apps de captura se instalan por versiones separadas: leen la selección en ejecución y no importan código de `~/.local/share/orbit/app/`.
- Los tokens viven en `apps/wysun/wysun_theme.json` (con `theme_core.py`); hay una copia idéntica en `apps/capture/loomrec/ui/` (`tests/test_theme_tokens.py` lo comprueba). Quickshell lee los colores de `~/.local/state/wysun/scheme.json` (`apps/shell/services/Colours.qml`). `tests/test_theme_literals.py` rechaza colores literales; las excepciones llevan `theme-exception: motivo`. Guía: `docs/themes.md`.
- Comprobaciones relevantes: `python3 -m unittest discover -s tests -v`, `python3 -m unittest discover -s tests/wysun_app -t tests`, `python3 -m unittest discover -s tests/shell_bridge -t tests`, `QT_QPA_PLATFORM=offscreen python3 tests/utility_ui.py`, `python3 tests/check_manifest.py`. Ejecutar también `python3 apps/capture/run_tests.py` y `python3 tests/wysun_installed_smoke.py`, con medios serializados. Las pruebas de sockets y escritorio necesitan acceso a la sesión; un bloqueo del sandbox no demuestra un fallo del producto.
- La sesión Wysun / Hyprland usa `apps/shell/` y el componente `wayland`, activo por defecto. No cambiar el login ni el gestor de acceso, no instalar dependencias del host ni reiniciar audio/portales sin autorización expresa. Validar con HOME/XDG temporales y medios sintéticos; pruebas de medios/compositor serializadas.
- El registro de sesión es independiente y reversible con `installer/session_registration.py`; nunca modificar por esa vía la sesión predeterminada ni el gestor de acceso. `docs/wayland.md` detalla preparación y recuperación.
